# Tonari の独立レビュー

Codex はすべての PR で、マージ前に差分と影響先を OpenAI の `review-agent` に渡します。構文解析・展開・プロセス・FD・シグナル・入力・履歴・補完の重要な変更時と、分野別監査の終了前には、未変更の関連コードも独立したコンテキストで調べます。起動するのはリポジトリの AGENTS.md を読む開発用 Codex です。シェルの起動やユーザーの打鍵でレビュー処理は走りません。[英語の運用手順](../.agents/skills/tonari-review/SKILL.md)

1. 担当者は対象ソース、仕様、優先順位を渡します。過去の所見や修正差分、実装者の判断、答えを示すテスト名は手元に留めます。過去の問題を使う試験では、修正前のソースとビルド入力を Git 履歴のない場所に取り出します。レビュアーはソースをたどり、関数・発生条件・予想する結果・対照入力を**計測前に担当者へ送ります**。
2. ベンチが Bash より速い経路も調べます。入力サイズを N、2N、4N とし、反復数は別に変えます。繰り返す処理は、通常の重複のない設定で同じ要求を続けて2回送り、1回の内側と呼び出しをまたぐ仕事を個別に数えます。極端な入力の方が遅くてもこの対照の結果を残します。各回の走査・再解析・ソート・コピー・システムコールの回数をコードか計装で確認します。`case` は分岐数と一致位置、`[[ ]]` は文字列・glob・正規表現と末尾不一致、文字列展開は長さ・置換数・結果長・日本語・絵文字を変えます。履歴・補完・glob は件数、偏り、初回、再利用、更新直後を比較します。パイプ・リダイレクトでは小容量・大容量、親側の準備、子の起動、I/O 待ちを調べます。
3. 実際の入力経路を使い、引数の個数と境界、終了値、stderr、親に残った変数・cwd・FD、ファイル、端末状態など、その機能で見える結果を照合します。途中失敗や割り込み、二度目の実行でも確認します。Bash の版、モード、該当する GNU ソース、POSIX の規定と Tonari の仕様に沿って判定します。両者に共通するバグ、UTF-8 専用などの意図した差には観測結果と理由を残します。
4. リファクタでは責務や中間状態を丸ごと消せるか、規則の重複をなくせるかを見ます。効果はコードの簡潔さ、消えた不整合、または計測値で示します。速度は入力の引っかかり、履歴・補完、起動、ファイル名展開、プロセスと I/O、変数・関数・コマンド置換、スクリプト全体の順に重視します。
5. 仮説を受け取った担当者は既存のテスト・ベンチと突き合わせます。変更前・変更後・Bash を同じネイティブ環境で順序を入れ替えながら測ります。目標は Bash の所要時間の 1/2〜2/3 です。短い処理は実行中シェルの反復と利用者の実待ち時間、OS 待ちは絶対時間と内訳を記録します。対話機能は PTY で入力から画面反映までを測ります。Rosetta は動作確認に使います。
6. 指摘・棄却した仮説・未計測の条件を区別し、修正後に対象経路を再確認します。抜き打ち試験は正解を事前に固定し、箇所・条件・再現入力・原因で採点します。追加発見も別途照合します。記録には見逃し、誤検出、所要時間と取得可能な利用量を含めます。発見手順を変えたら、答えを渡していない別の題材で再評価します。

## 専門資料の使い分け

`python3 tools/review-skill.py --list` で出典・固定リビジョン・ライセンスを表示します。`python3 tools/review-skill.py rust-hot-path references/allocation-reduction.md` のように必要な本文だけを読みます。開発用ツールの導入で Cargo の依存は増えません。[選定理由と参照資料](../.agents/skills/tonari-review/references/sources.md)

| 用途 | 使う資料 |
| --- | --- |
| 差分レビュー | OpenAI の `review-agent`。既存コードの監査は別コンテキストで実施 |
| 性能と設計 | `rust-performance` で原因を測り、`rust-hot-path` で対策を選定。所有権や責務、エラー処理は `rust-best-practices` |
| Linux x86-64 | Intel の `linux-perf`。Intel・AMD ともにその実機の `perf list` と試験実行で使えるイベントを選定。権限・仮想化・カウンタの多重化も記録 |
| macOS arm64 | `instruments-profiling`。CPU は Time Profiler、プロセス起動・パイプ・I/O・スケジューリング待ちは System Trace。録画と表のエクスポートは Xcode の `xctrace` で可能。`profiler-guide` の集計・照会用 MCP プラグインは任意 |
| 試験入力 | Bash は `bash-ops`、POSIX sh は `posix-shell-pro`。判定は実装・規格・Tonari の仕様に戻る |
