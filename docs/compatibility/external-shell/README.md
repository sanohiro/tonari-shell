# External shell comparisons / 外部試験による Bash 比較

These tests use Tonari's Bash entry point. The [yash comparison](../yash-posix/) covers the separate `sh` entry point. この試験では Bash として起動し、対話操作・組み込み・言語機能を調べています。

## Results / 結果

The reference was GNU Bash 5.2.21 on Ubuntu 24.04 x86-64 and GNU Bash 5.3.20 on macOS 15 arm64. Each platform ran 4,659 cases against both shells. The two-thirds count uses elapsed time, with one first-response observation per paired visible input in the upstream PTY run and five interleaved trials per ordinary script case.

| Host | Suite | Both met expectations | Bash only | Tonari only | Neither | Comparable timings | Tonari ≤ ⅔ Bash | Tonari > Bash |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Linux x86-64 | bensch interactive | 973 | 10 | 28 | 3 | 973 | 272 | 268 |
| Linux x86-64 | bensch builtins | 831 | 2 | 0 | 42 | 818 | 799 | 0 |
| Linux x86-64 | Oils | 2431 | 296 | 2 | 41 | 1968 | 1545 | 27 |
| macOS arm64 | bensch interactive | 923 | 10 | 25 | 56 | 923 | 289 | 310 |
| macOS arm64 | bensch builtins | 830 | 3 | 0 | 42 | 817 | 768 | 4 |
| macOS arm64 | Oils | 2300 | 262 | 36 | 172 | 1850 | 1450 | 51 |

For Oils, the ordinary expected result (`PASS` for both) matched in Linux x86-64 2,182 and macOS arm64 2,069 cases. The larger first column includes accepted Bash-specific annotations. 日本語での「両方合格」は、そのケースで両方が上流の該当する期待値を満たした件数です。「両方失敗」は未合格です。速度比の列には比較条件を満たしたケースだけを数えています。

The stock bensch builtin CLI reported 567 passed, 38 failed and four skipped for each shell on each host. The per-case replay contains two Bash-only verdicts from `exec` examples reopening `/dev/tty` with no controlling terminal. Both shells returned the expected output and status in all 11 trials per case and platform once the original commands ran inside a controlling PTY. On macOS there is one additional Bash-only builtin verdict. Both shells report the same running job for `sleep 60 & jobs` and exit successfully, but Bash 5.3.20 inserts three more spaces before the command name. The Linux Bash 5.2.21 and Tonari bytes match. [Terminal supplement](https://github.com/sanohiro/tonari-shell/actions/runs/45713431372)

組み込みの個別試験で Bash だけが通った2件は、`/dev/tty` を開き直す入力です。制御端末なしではエラー文の違いが出ます。制御端末ありでは標準出力を戻す例も標準エラーを戻す例も、両シェルが全回で期待した内容を返しました。macOS の残り1件は `jobs` の表示幅が3スペース違うためです。

## What ran / 試験範囲

| Suite | Workload and oracle |
| --- | --- |
| bensch interactive | All 1,014 cases from 15 YAML files. The upstream Bash profile, key decoder, steps, expectations, timeouts and session reuse rules run against each release in a PTY. Shards split on ten-test boundaries. The runner reuses sessions on Linux and opens one session per case on macOS. |
| bensch builtins | The stock CLI runs once against each shell with the same GNU Bash reference. A second pass extracts all 879 assertions from the portable and extended scripts. It runs 875 and records four upstream interactive-history skips. This includes fortsh-only assertions, the stress script with its missing harness restored, and isolated replays of the exec and non-TTY job cases. |
| Oils | All 2,765 cases in files naming Bash in `compare_shells`, plus five `redir-order` cases. The pinned corpus contains 3,971 cases in 223 files. The remaining 1,201 have no active Bash comparison and are listed in the manifest. |

bensch の対話試験は全件を実行します。組み込みでは、上流の集計と、各スクリプトが展開したコマンドを使う個別試験を両方残します。個別試験は各回で同じパスに作業環境を作り直し、参照シェル・試験対象・前提ファイルを明示します。上流の出力正規化には引数の欠けた `sed -e` があり、両出力が空として一致することがあります。個別試験は終了状態と実際のバイト列も保存します。[bensch harness](https://github.com/tenseleyFlow/bensch/blob/c8e2a1ea493fc0dceb9af645dc445e619cb449e7/suites/builtins/test_harness.sh)

Oils supplies the parser, Bash-specific assertions and grading, including its `OK`, `BUG` and `N-I` annotations. Identical script bytes arrive through a pipe. Each shell runs under the same basename, with its own `bash` on PATH so nested `$SH` calls reach the tested executable. The helper programs and Python 2 runtime are identical. Five alternating trials include process creation, script input, external utilities, output collection and exit. A timed-out or output-limited case retains its failure record. [Oils runner](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/test/sh_spec.py)

Oils の `PASS` は標準期待値への一致です。`OK`・`BUG`・`N-I` などは、その Bash 向け注記に一致したことを表します。両者の結果が同じでも上流の期待値に合わなければ両者失敗です。UTF-8 専用という既存方針は個々の入力に照らして判断します。期待値に合わなかったケースを一括して例外扱いすることはありません。[互換性方針](../../compatibility.md#intentional-differences)

## Reading a case / 結果の読み方

[Linux x86-64 cases](ubuntu-24.04.tsv.gz) · [macOS arm64 cases](macos-15.tsv.gz) · [Counts by spec file](groups.tsv) · [Differences and observed output](differences.tsv.gz) · [Execution sites and review notes](sites.tsv) · [Previous and final timings for every case](before-after.tsv.gz) · [Changed verdicts](changes.tsv.gz) · [Helper timing controls](helpers.tsv.gz) · [Compiler profile trial for every script](profiles.tsv.gz) · [Physical Mac replays](mac-replays.tsv)

The two compressed TSVs contain a row for every executed case. `bash` and `tonari` preserve each verdict. `both` means both met that assertion, `bash-only` and `tonari-only` identify a difference, and `neither` means both missed. The script comparison additionally checks raw stdout, stderr and status. The verdicts refer to the first trial and the `unstable` column lists shells whose outcome changed in later trials. Only stable, byte-identical outcomes accepted by both receive a timing ratio. Look up an Oils case at its source line, or a bensch case by its name and index. Oils and builtin indices start at zero. PTY indices start at one.

For PTYs, `bash_ms` and `tonari_ms` give the median time from a write to the first output byte for corresponding input events in one case. The observation thread relays bytes to the original matcher. A key that produces no new bytes has no latency value. `samples` counts paired visible events. The `*_case_ms` columns include driver waits. The artifacts contain each individual event. A redisplay can satisfy an unanchored upstream expression. The outcome-checked cursor, completion and resize probes separately wait for the completed value or visible result. [Timed witnesses](../../../tools/ci/spec-hot.py)

スクリプトの時間比は Tonari 時間 ÷ Bash 時間です。対話試験の時間は、同じ入力イベントに対して最初の1バイトが届くまでの値です。何も描画しないキーには時間を付けません。入力のエコーでも期待値に一致する場合があるため、確定した値まで検証する測定を併記します。上流の Bash プロファイルは `HISTSIZE=0` なので、大きな履歴の検索は履歴を有効にした別の PTY でも測ります。[bensch Bash profile](https://github.com/tenseleyFlow/bensch/blob/c8e2a1ea493fc0dceb9af645dc445e619cb449e7/profiles/bash.yaml)

Each case also lists sites reached during an untimed instrumented replay. The normal distributed binaries produce the timings. The PTY observer uses a fresh shell per case, so a case that depends on session reuse can visit different sites. Site IDs map to functions and the associated checks for copying, parsing, lookup, allocations, system calls and redraws. Raw logs retain the observer result. A timeout or output limit can end a case before the untimed observer runs. The `source_mentions` column lists helper names found in the script text, or the kinds of PTY steps and keys the upstream case sends. The separate compiler sweep pairs the shipping `-O2` build with `-O3` on each of the 3,645 script cases, preserving the original upstream helpers. Its three trials per build alternate on the same runner. A ratio requires stable matching output and status between both builds. Grammar coverage and compiler-profile comparisons use separate columns. The previous and final timings come from separate native jobs. Only the Bash and Tonari measurements within a given job share a runner. 各ケースの `sites` から実行経路と確認したコストを引けます。トレースと計測には別の実行ファイルを使っています。

## Confirmed differences / 再現した動作差

The Linux Oils results include three direct witnesses to Tonari's existing UTF-8 policy. In `unicode/0`, the valid script runs, then its version with an invalid UTF-8 source byte reports `expected UTF-8 command text`. In `unicode/3` and `unicode/4`, the out-of-range scalar U+110000 and the surrogate U+DC00 in ANSI-C quotes report an invalid Unicode escape. These cases remain Bash-only in the counts. In `unicode/5` and `unicode/6`, the corresponding `printf` and `echo -e` probes produce empty text. Whether those builtins should diagnose the invalid escapes is a separate question. [Oils Unicode cases](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/unicode.test.sh) · [Tonari UTF-8 contract](../../compatibility.md#intentional-differences)

既存の UTF-8 方針に沿う差も外部試験の点数には残しています。無効なソースや Unicode スカラーを拒否する理由と、組み込みが空の文字列を出して成功する挙動の妥当性は、個別に判断します。

In the macOS interactive run, 26 of the 56 joint failures expected a nonzero `EXIT=` value. Upstream inserts an `echo __STEP_SYNC_…__` between certain successive command lines on Darwin. In `posix_basic_auto/67`, both shells therefore print `EXIT=0`. A direct physical-Mac PTY replay of `true && false` followed by a status print returned 1 in Bash and Tonari, and 0 in both after inserting that marker. Another 26 joint failures are in the history file, run with the profile's disabled history. The upstream outcomes remain in the matrix. [Darwin synchronization code](https://github.com/tenseleyFlow/bensch/blob/c8e2a1ea493fc0dceb9af645dc445e619cb449e7/framework/runner.py#L366-L390)

macOS の両者失敗には試験側の影響もあります。直前の終了値を読む2行の間にランナーが同期用の `echo` を実行するため、その終了値が見えてしまいます。比較表には上流の失敗を残し、元のコマンドを直接入力した場合の結果を併記しました。

A conventional indexed assignment now handles `x=1; y=2; a[$x$y]=okay` and reads back `okay` from `${a[12]}`. Compound array literals have an additional ordering rule. With `i=1; a=([100+i++]=$((i++)))`, Bash 5.2.37 sets element 102 to 1. Tonari sets element 101 to 2. The indexed-write fix leaves this separate expansion-order gap open. [Oils array literal cases](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/array-literal.test.sh)

`declare -r v=abc; printf '<%s>\n' "${v@a}"` prints `<r>` in Bash 5.2.37. Tonari diagnoses a bad substitution. With an initially empty environment, `: last; printf '<%s>\n' "$_"` prints `<last>` in Bash and `<>` in Tonari. These witnesses expose missing Bash behavior. 複合配列リテラルの評価順、属性展開 `${v@a}`、直前の引数 `$_` は通常の Bash モードで再現した互換性課題です。[Bash parameter cases](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/var-op-bash.test.sh) · [Special variables](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/vars-special.test.sh)

A PTY witness also found a vi editing gap independent of the bensch display matcher. In vi mode, define `s() { printf '<%s>' "$@"; }`, type `s hello world`, press Escape, then type `0wcwgoodbye` and Enter. Bash 5.2.37 passes `goodbye` and `world` to the function. Tonari passes only `world`. vi モードの単語移動と変更には未対応の組み合わせがあります。実際に関数が受け取った引数で確認しました。[Upstream vi cases](https://github.com/tenseleyFlow/bensch/blob/c8e2a1ea493fc0dceb9af645dc445e619cb449e7/suites/interactive/editing/vi_mode.yaml)

An Oils annotation can also explain a Tonari-only verdict. In Linux `array-assoc/34`, Tonari's empty output arrays match an older Bash `BUG` annotation. GNU Bash 5.2.21 successfully preserves the backslash key and its value. In `process-sub/4`, Tonari returns the ordinary upstream output, while the installed Bash prints one additional line. A Tonari-only score by itself establishes which expectation matched. Linux の Tonari だけが通った2件のうち一方は、過去の Bash の不具合に付いた注記への一致です。期待値の内訳も表に残しています。[Associative array case](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/array-assoc.test.sh) · [Process substitution case](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/process-sub.test.sh)

Two Oils strict-options assertions expect status 1 from a top-level `return`. Modern GNU Bash reports 2. Tonari now returns 2 too. Both shells therefore miss these two upstream expectations. トップレベルの `return` は現行 Bash の終了値に合わせました。古い期待値との不一致を表に残しています。[Upstream strict options](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/strict-options.test.sh)

Comparing the earlier and final releases, the Bash-only Oils count fell from 318 to 296 on Linux and from 285 to 262 on macOS. The interactive Bash-only count fell from 16 to 10 on both. Both `strict-options` changes above match the reference Bash status. The other newly failing Tonari verdict on macOS was `background/17`. It starts children with nominal 90 ms and 30 ms sleeps and expects two `wait -n` calls to return 3 then 9. Both shells returned 9 then 3 on the first final trial. Both also varied across trials. The table retains the first verdict, and the case receives no timing ratio. [Changed verdicts](changes.tsv.gz) · [Upstream background cases](https://github.com/oils-for-unix/oils/blob/d114978ca467143f171a835cbcbe8ab6ccc009a7/spec/background.test.sh)

変更前に Bash だけ通った Oils の件数は Linux で318件、macOS で285件でした。変更後にはそれぞれ296件、262件です。`wait -n` の完了順が試行ごとに変わったケースも記録に残し、速度の合格件数には含めていません。

## Reproduction / 再実行

From the repository, dispatch `native-benchmarks.yml` for `ubuntu-24.04` and `macos-15`. Select `bensch-0` through `bensch-7`, `spec-builtins`, `oils-0` through `oils-3` and `spec-hot`. The optional `oils-argv` and `oils-printenv` jobs each replace one Python helper. The `spec-tty` job replays the two terminal-dependent builtin assertions with a controlling terminal. References, checksums and release checks live in the drivers. The shell version, architecture, executable size and artifact hash accompany each run. [Suite setup](../../../tools/ci/external-spec.sh) · [Distribution build](../../../tools/build-release.sh)

Download the artifacts from the [primary run](https://github.com/sanohiro/tonari-shell/actions/runs/45712166512). Use the [macOS script artifacts](https://github.com/sanohiro/tonari-shell/actions/runs/45718497500) for the four Oils shards and `spec-builtins`. These jobs used the same runtime source after correcting an empty-array expansion in the system Bash build driver and a process-group cleanup race in the timing driver. With PyYAML installed and the pinned bensch checkout available, run `python3 tools/ci/spec-report.py ARTIFACTS ARTIFACTS BENSCH_CHECKOUT OUTPUT` to rebuild the tables. To reproduce all comparison files, add `--baseline-scripts PREVIOUS_SCRIPTS --baseline-pty PREVIOUS_PTY --controls HELPER_ARTIFACTS --profiles PROFILE_ARTIFACTS`. The [Linux profile sweep](https://github.com/sanohiro/tonari-shell/actions/runs/45716192920) uses `oils-profile-0` through `oils-profile-3` and `spec-profile-builtins`. On the physical Mac the same paired driver used `--runs 3`, with the `-O2` executable first and the `-O3` executable second. Store its builtin and Oils outputs as `physical-m1-spec-profile-builtins/profiles.jsonl` and `physical-m1-oils-profile-all/profiles.jsonl` in the profile directory. The previous [script](https://github.com/sanohiro/tonari-shell/actions/runs/45709333650) and [PTY](https://github.com/sanohiro/tonari-shell/actions/runs/45708907820) runs precede the runtime fixes. For the earlier macOS builtin baseline, use the [complete 875-case replay](https://github.com/sanohiro/tonari-shell/actions/runs/45719965456) of the same revision and name its directory `macos-15-spec-builtins`. Collect both platforms’ [argv](https://github.com/sanohiro/tonari-shell/actions/runs/45711396889) and [printenv](https://github.com/sanohiro/tonari-shell/actions/runs/45714213442) artifacts, using the macOS rerun for argv. The join checks that every selected case is present exactly once. 再集計時は片方のシェルしかないケース、欠落、重複があればエラーになります。[Native run](https://github.com/sanohiro/tonari-shell/actions/runs/45712166512)
